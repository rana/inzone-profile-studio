# Foundations

Make a look easy to recognize, keep, recover and hand to another person. The
keyboard should support writing and thinking without becoming another project
the owner must manage. Start with [using the studio](../README.md); see the
[research queue](RESEARCH.md) for bounded next steps.

## What we protect

**Amber Hinge + Rose is the accepted keeper.** Plain Amber Hinge is the simpler
accepted reference. Exploration creates alternatives; it does not silently revise
these designs or change an owner's active keyboard. Acceptance belongs to a
particular physical trial, not every visitor or every lighting environment.

All 81 physical keys stay illuminated. Legibility comes before spectacle. A few
recognizable landmarks are more useful than assigning a separate meaning to
every key. Keep left/right modifier pairs consistent and change one relationship
at a time so a comparison can answer a question.

Color meaning is a design hypothesis, not universal psychology. Red for stopping
or deleting and warm modifier accents are useful here because the owner found
them meaningful. Letter frequency alone does not tell us what should be bright.
Tasks, reach, habits, glance typing, ambient light and personal preference matter.
Screen RGB values do not measure the keyboard's apparent hue or brightness.

Label records as **preference**, **physical observation**, or **hypothesis**.
For example, preferring rose Shift keys is a preference; noticing their contrast
in low light is an observation; predicting faster navigation is an untested
hypothesis.

## What the studio knows

A portable palette describes colors for physical keys. A native Sony export
describes a particular profile's settings. A preview, download, example slot plan
or successful file comparison does not establish live hardware state.

Prepare an import from the recipient's own fresh export of the intended slot.
The person identifies that slot; its number cannot be inferred from a profile
name. Preserve mappings, Main/Fn behavior, performance, macros, reserved entries
and unrelated effects. Refuse unknown formats. Compare every field in a fresh
readback, then assess physical behavior separately.

Within the studio, private exports stay in browser memory. Public Git contains the app, palettes
and generic evidence summaries, not native backups, photographs or transcripts.
Unattended continuation improves software, documentation or previews; it never
writes daily hardware. Actual trials require a user-selected design and local
connection. macOS behavior requires an actual Mac test.

## How we decide

Keep browsing and sharing simple; expose editing and native preparation when
needed. Favor a recoverable artifact and a clear next action over clever controls.
Ask Claude to challenge a consequential design choice with relevant evidence;
agreement between models is not physical validation.

Stop when the question is answered. Keep an existing design when a variation is
indistinguishable or adds no benefit. An hourly timer is permission to make useful
progress, not an obligation to manufacture palettes or notifications.
